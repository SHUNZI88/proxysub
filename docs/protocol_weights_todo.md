## 一、约定内容（2026-10-15，用户与 AI 达成）

用户指令原话：
> 「好的，那 7 轮后你再评估实施」

**含义**：协议维度的权重化（按协议分层设定采样/评分权重）**暂不实施**，
先由 P2-a/b/c 基建自然积累跨轮证据；**待 `protocol_history.json` 中某协议

## 二、复查条件（硬性门槛，定义于 config.py）

某协议**同时**满足以下两条，方可进入"协议权重化评估"：

| # | 条件 | 常量 | 值 |
|---|---|---|---|
| 1 | 累计样本 | `PROTOCOL_WEIGHT_MIN_CUM_SAMPLE` | ≥ 50 |
| 2 | 出现轮次 | `PROTOCOL_WEIGHT_MIN_ROUNDS` | ≥ 5 |

> 此外须在 `protocol_history.json` 留痕（可审计、可复算）。

---

## 三、如何检查（任何 AI 会话可执行）

```bash
cd <仓库根>
python3 -c "
import json
h=json.load(open('protocol_history.json'))
for k,v in sorted(h.items(), key=lambda x:-x[1]['tested']):
    ok = v['tested']>=50 and v['rounds']>=5
    print(f\"{k:10} rounds={v['rounds']:3} tested={v['tested']:4} {'✅达标' if ok else '未达标'}\")
"
```

若出现 `✅达标` → 立即提示用户，并准备评估材料（见第五节）。

## 五、达标后应评估什么

1. **跨轮方向一致性**：读 `protocol_history.json` 的 `recent`，核对各轮通过率是否同向；
2. **置信区间收敛度**：读报告 `by_protocol[*].ci95_low/high`，区间是否已收窄到可决策；
3. **因果解耦**：结合 `by_source`，区分"协议好"还是"恰好来自好源"；
4. **反身性检查**：确认拟定的权重规则不会形成"高通过率→更多配额→更显著"的自我强化；
5. **结论**：给出"实施 / 部分实施 / 继续观察"的建议，并写入评估报告。

## 六、同时保留的既有结论（勿遗忘）

- **不提高 vless 比重**：vless 通过率最低（2.8%），提高会降低总产出（报告 §十一）；
- **可考虑的是**：温和降低 vless 待测占比（soft cap），把额度让给源侧有货的高通过率协议；
- **一切协议层调整**须待本看板"达标"后，以证据驱动方式实施。
